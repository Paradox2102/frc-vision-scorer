SAM 3 is the default: best identity in full-match A/B testing (6/6 confirmed on qm24) at roughly half the wall-clock. SAM 2.1 remains as the legacy fallback.
The server default comes from TEAM_READER (Jev unless the server was started with TEAM_READER=vllm). Jev and Clef pick the team from the full match roster in the cloud and never start vLLM; Jev needs JEV_TYPESAFE_API_TOKEN, Clef needs CLOUDFLARE_ACCOUNT_ID / CLOUDFLARE_API_TOKEN in .env. If a cloud reader's quota or auth fails, reads stop for that job (no local fallback). vLLM reads on the local GPU with the model picked below.
Which model reads bumper numbers. All are served by the vLLM reader in HF format; the default (Qwen3-VL-4B) is fastest. Models marked “needs download” are fetched from Hugging Face on first use, so the first run is slower.
Frames per GPU-resident tracking window. A VRAM-fit knob, not a speed knob — identity was flat from 150–800 in testing. Tracking has the whole GPU (the vLLM reader is stopped during this phase), so the 400 default is fine; leave empty.
Smaller = faster, coarser masks; larger = slower, finer masks. Sizes marked “needs download” have no checkpoint on disk yet.
> 0 keeps SAM2 tensors on the GPU (no CPU offload, much faster per frame) and raises frame-skip so the match fits in this many tracked frames. ~12 MiB VRAM per frame, e.g. 1200 ≈ 14 GiB. Trades temporal resolution for speed.
Process only the autonomous window (located via the match clock) instead of the full match. Use this to compare against Manta human-scouted auto paths. Needs a clean clock lock on the auto countdown.
Draw the reprojected field (perimeter, grid, hubs, bumps, towers, trenches) over the main view — baked into the live stream and the recorded replay. Use it to check the calibration and results line up with the real field.
