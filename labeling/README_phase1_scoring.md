# Phase 1 labeling workflow (team scoring)

This workflow labels the minimum data needed to support:
1. per-team scored-ball counts
2. robot team-number identification
3. counting **only** made shots into the center container

## 1) Start Label Studio with Phase 1 config

From repo root:

```bash
LABEL_STUDIO_LOCAL_FILES_SERVING_ENABLED=true \
LABEL_STUDIO_LOCAL_FILES_DOCUMENT_ROOT="/Users/ship/development/projects/frc-vision-scorer" \
labeling/.venv/bin/label-studio start labeling/ls_phase1_scoring --init \
  -l labeling/label_config_phase1_scoring.xml \
  --username ship --password fuelball \
  -p 8080 -b
```

Open: <http://localhost:8080>

## 2) Import tasks

Use candidate windows generated by:
- `scripts/extract_candidate_shot_windows.py`
- `scripts/batch_extract_shot_windows.py`

Import task file:
- `data/shot_candidates/<run_name>/labelstudio_tasks.json`

## 3) Annotation rules

### Regions
- `robot`: box around each visible robot body
- `bumper_number_roi`: tight ROI around visible team-number text on bumper
- `center_goal_roi`: box around the **center container opening** (where makes count)
- `fuel_ball`: optional, useful for goal-entry training

### Region metadata
- Fill `region_team_number` where readable
- Set `region_alliance` on robot and bumper ROIs
- Set `region_occlusion` to reflect visibility quality

### Frame-level event
- `made_shot_event = made_shot_center` **only** on frames where a ball enters the center container
- Set `shot_team_number` if attribution is known
- Add `shot_ball_track_id` when available
- Use `shot_confidence` to indicate uncertainty

## 4) Export

Export as JSON, then normalize with the schema in:
- `labeling/annotation_schema_phase1.json`
- `src/schema/phase1_annotation.py`

(Current conversion script is intentionally left as a follow-up after first annotation pass.)
